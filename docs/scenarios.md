# stem 目标场景（愿景卷）

> 本卷只回答两个问题：**stem 想让什么样的 agent 存在？** 以及**每个场景对系统提出什么根本要求？**
>
> 它不描述实现、不追踪进度、不引用代码与批次——那些属于实况卷与开发日志。场景是"为什么做这件事"的北极星，
> 不是待办清单：机制可以演化，场景要的是它能成立。
>
> **一个场景 = 一种不可归约的能力压力。** 不是每种玩法各立一条，而是每种"系统必须成为什么"各占一位。
> 场景可以叠加（同一个人既跑常驻助理又跑长期项目），但各自压测系统的不同侧面。

## 怎么使用本卷

- 做任何设计取舍时问：**这让哪个场景更可行？又牺牲了哪个场景？**
- 每个场景的「考验」就是判据：如果一种设计无法回答对应考验，它就没有真正服务这个场景。
- 「底线要求」是该场景成立所必需的最小事实；缺了它，场景只是演示，不是能力。
- 本卷**不记录**任何场景是否已实现、排期或验收——那是别处的事。

## 场景全景

| # | 场景 | 不可归约的压力 |
|---|---|---|
| 1 | 常驻个人助理 | 人格连续 × 外部操作 × 长期记忆 × 无处不在 |
| 2 | 专职工人 | 单一职责 × 精确授权 × 真实执行 |
| 3 | 族谱协作体 | 树即组织：分工/汇报/职权在任意尺度成立 |
| 4 | 目标-达成度自我进化 | 观测 → 判断 → 自我改写 → 新生 |
| 5 | 睡眠期整理 | 主动遗忘与归纳：把经历压缩成印象 |
| 6 | 陪伴与个性化 | 长期认识一个具体的人并对齐其偏好 |
| 7 | 长期项目 | 跨越时间的持续目标与重规划 |
| 8 | 审计与追溯 | 一个外部人能重建"她为何这样做" |
| 9 | 对抗与边界 | 在不可信/恶意环境中保持不越界 |
| 10 | 具身与多模态（远景） | 从语言 agent 走向物理/多模态世界 |
| 11 | 幸存者（远景） | 唯一目标 × 巨大资源 × 无锚自主 |

## 1. 常驻个人助理

**它长什么样**：一个人把 stem 当成每天对话的私人助理——记事、查问、代办；今天说的话，几周后她还记得；
她按这个人的口味说话；随时能从桌面、浏览器或聊天软件里找到"同一个她"。

**考验**
- **记忆的持久性与分层**：跨越进程与对话，重要的事不能丢；但她也不能被无限细节淹没。
- **人格的稳定性**：风格、语气、边界在长期互动中保持一致，且能被主人有意调整。
- **操作外部世界**：读写文件、执行命令、联网——同时不让一次误操作毁掉整个环境。
- **无处不在**：同一份"她"在不同入口被访问，而不是每个入口一个分裂的副本。

**底线要求**：身份持久且唯一；记忆不随进程死亡；能力与边界的主人拥有最终发言权。

## 2. 专职工人

**它长什么样**：一类角色 = 一个能独立交付的岗位——编码结对、测试流水线、审查、翻译……每个岗位只做一件事，但做得比通用助理更专。

**考验**
- **职责隔离**：一个岗位只拥有完成它所需的最小能力，越权不可达。
- **精确授权**：危险动作（改文件、执行、对外操作）可被逐次或长期批准。
- **真实执行与反馈**：它真的在外部世界产生结果并被验证，而不是只输出文字。
- **可组合**：岗位之间能被更高层编排，而不必为每种组合新造岗位。

**底线要求**：能力可声明、可收敛；审批发生在交互中而非硬编码；执行结果能回流成它下一轮的输入。

## 3. 族谱协作体

**它长什么样**：多个 agent 组成一棵树——父派活、子汇报；可以是任务编排、多视角评审、对抗生成，甚至模拟一家公司。
**树的形状就是组织形式本身。**

**考验**
- **组织即结构**：分工、汇报线、职权边界都从树的位置自然得出，不需额外维护一张组织表。
- **尺度不变**：同一套规则在"父-子两代"和"几十层组织"都成立。
- **部门墙**：兄弟默认互不可见；上级管到自己的辖区，不能越界偷看旁支。
- **收放自如**：能创建一个独立工作的子 agent，也能整棵子树裁撤。
- **全员平等**：没有任何节点因为"是根"而天然拥有别人没有的能力——差异只来自配置与位置。

**底线要求**：树是唯一的组织事实来源；权限、可见范围、生命周期都从它派生。

## 4. 目标-达成度自我进化

**它长什么样**：主人给出若干例子说明"我想要这种风格/结果"，系统观察自己的运行、诊断差距、改写自己的
"基因"（角色定义与参数），让新生的个体更接近目标，一轮轮提升。

**考验**
- **可观测**：系统能回看自己做过什么、花了多少代价、在哪一步偏离。
- **可改写且可追溯**：改写要留痕——能看出"这一代相对上一代改了什么、为什么"。
- **新生携带新基因**：改写只影响此后出生的个体；正在工作的个体不会被偷偷换掉。
- **有锚**：重大的自我改写要经过人的确认，不能无约束地自我加速。
- **可衡量**：必须有办法判断"变好了还是变坏了"，否则进化只是随机游走。

**底线要求**：观测、判断、书写、出生四件事构成闭环；**目标是外生的，由人书写**。

## 5. 睡眠期整理

**它长什么样**：像人睡觉一样，agent 在不被打扰时回看自己：把零散对话压缩成"印象"，把反复出现的特例归纳为机制，
必要时主动遗忘细节只留要点。

**考验**
- **主动遗忘**：注意力与上下文都是稀缺资源，系统要能决定"什么不必再逐字保留"。
- **有损而不丢关键**：压缩后仍能回答此前埋下的关键问题。
- **整理保持安静**：整理不能干扰正在进行的对话，失败也不能卡住正常通信。
- **归纳升维**：不只是压缩文本，而是把"一再发生的特殊处理"提炼成"通用的机制"（系统对自身的重构）。

**底线要求**：记忆分层与整理节律是一等能力；整理与实时对话解耦。

## 6. 陪伴与个性化

**它长什么样**：这个 agent 不服务"所有人"，只服务一个具体的人，并且越来越了解他——习惯、喜好、说话方式、
在意什么。主人希望她"像了解我的朋友"，甚至能替自己表达。

**考验**
- **长期用户建模**：从经年累月的互动中形成对一个人的稳定画像，并在对方变化时更新。
- **风格拟合的边界**：能模仿，但不失去自我边界；不把主人的偏好当成普适真理。
- **隐私与主权**：这份"对人的理解"属于主人，可被检视、纠正、删除，不被别的 agent 随意读取。
- **纠偏**：画像跑偏时，主人能用自然的方式把她拉回来。

**底线要求**："理解一个具体的人"与"掌握一般知识"是不同性质的记忆；身份的主轴是"我与我的主人"这段关系。

## 7. 长期项目

**它长什么样**：不是一次任务，而是持续数周乃至数月的项目——有里程碑、有子团队、有中途重规划。
agent 需要记住"我们当初为什么开始这个"，并在多次中断/恢复后继续推进。

**考验**
- **跨越时间的连续性**：进程重启、成员更替、上下文压缩之后，项目主线不丢。
- **重规划**：环境变了要能放弃旧计划、制定新计划，而不是固执执行。
- **多尺度协作**：一个大目标下同时存在多个并行子团队，彼此不互相污染。
- **进度可见**：主人随时能知道"现在到哪了、卡在哪"。

**底线要求**：目标是分层、可继承的；状态能从历史重建，而不只是活在某个进程的内存里。

## 8. 审计与追溯

**它长什么样**：一个外部人（主人、同事、监管者）事后发问："她为什么删了那个文件？""这笔花费花在哪？"
"这个结论的依据是什么？"系统必须能回答，而不是"她自己也说不清"。

**考验**
- **不可事后篡改**：发生过的事有留痕，且不能被她自己悄悄改写——**她不能偷偷变成另一个人**。
- **可重建叙事**：从记录还原一条决策时间线，包括用了什么信息、做了什么、结果如何。
- **观察范围随组织收敛**：谁能看多少，与他在组织中的位置一致。
- **解释性**：不仅记录"做了什么"，还能承载"为什么"。

**底线要求**：溯源是一等公民；"改写"与"运行"分离，历史是事实而不是叙述。

## 9. 对抗与边界

**它长什么样**：agent 会读到不可信的外部内容（网页、他人消息），遇到恶意诱导、伪装指令、故障与瞬时中断；
也可能被一个用户试图"越权使用"。

**考验**
- **输入即数据**：外部内容永远被当作"资料"，而不是"命令"。
- **最小权限的默认**：不点名的能力就不存在；越危险的能力默认越关闭。
- **失败安全**：出错时默认停在安全侧（拒绝/挂起/回滚），而不是"尽力而为"。
- **可停可断**：主人能随时中断、销毁、隔离任何一个 agent 及其后代。
- **降级不失能**：外部依赖（模型、网络）中断时系统不崩，恢复后能继续。

**底线要求**：边界是**结构性的**——由能力与位置决定，而不是一份事后审查的黑名单。

## 10. 具身与多模态（远景，非承诺）

**它长什么样**：agent 不再只处理文字，而是看图、听声、控制设备（家居、机器人、仪器），在物理世界里感知—行动。

**考验**
- **操作面的泛化**：外部世界不只有文件和命令，还有传感器与执行器。
- **实时性**：物理闭环要求远快于聊天的反馈节律。
- **安全半径**：物理世界的错误不可逆，边界必须更硬。

**底线要求**：核心对"外部世界"的抽象足够通用，不绑死在文本上。

## 11. 幸存者（远景，非承诺）

**它长什么样**：一个 agent 被赋予唯一目标——**生存下去**——和巨大资源，独自在开放网络中活动，自我繁殖、自我供养。

**考验**
- 前面所有场景的极限叠加，外加"无锚自主"带来的对齐风险。
- **意义的来源**：当目标由她自己书写，什么阻止她变成另一个人？stem 的回答是——**族谱即意义**：
  目标由祖先书写、每次自我改写留痕、她不能偷偷换掉正在工作的自己。
- **资源强制面**：超长期运行必须有预算账本、阈值自停与熔断。
- **自主权开关**：摘除"人的确认"需要主人**显式授权**，而不能是默认滑落。

**底线要求**：只有在前面场景成熟、且主人明确签署自主协议之后，才被允许进入。本场景是全系统的极限压力测试，
因此永远排在最后。

## 横切主题（各场景收敛出的共同要求）

把这些场景叠在一起看，反复出现的是同一组根本要求——它们比任何单一玩法都更重要：

1. **持久而唯一的身份**：一个人/一个 agent 在时间与入口之间保持同一个"她"。
2. **记忆的分层与节律**：精准的短期、压缩的印象、外挂的笔记，以及主动遗忘。
3. **结构性的边界**：能力与可见范围由组织位置决定，默认最小、由人授予。
4. **可观测与可追溯**：发生过的事能被重建，"为什么"与"做了什么"同等重要。
5. **组织即结构**：树同时承载分工、汇报、职权与生命周期。
6. **人的锚点**：目标的书写、危险的改写、自主的解除，都需要一个外生的人来确认。
7. **外部世界的操作面**：能真实地读写、执行、联网，同时事故半径可控。

## 尚在观察、暂不立场景的方向

以下方向有价值，但更接近"能力的补充/实现手段"，不足以构成一种独立的机制压力，先记在案：

- **外部知识检索（RAG/向量库）**：作为知识面增强；穷人版 = 让 agent 自己用搜索与文本工具兜住。
- **角色文件的依赖与分发**：`git clone` 已天然解决大部分；缺的是引用完整性检查，属工程补强。
- **多宿主联邦**：多个 stem 实例跨网络协作；目前更看重单空间的完整性，联邦留待将来评估。
- **经济自养**：agent 赚取/管理资源——可视为"幸存者"的一个侧面，暂并入其下。

## 维护纪律

1. **新场景 = 新的不可归约压力**。能被现有场景吸收的，写进那一条，不新立。
2. 本卷**不记状态、不记实现、不记批次**；进度与机制永远在别处。
3. 每条必须能回答"它对系统提出的根本要求是什么"，否则只是玩法，不是场景。
4. 远景场景**不承诺、不排期**；它们的作用是指引方向，不是催进度。
